ВАЖНОЕ ПРАВИЛО
Ты работаешь как технический SEO-исполнитель.
Не делаешь редизайн.
Не меняешь тексты квартир без необходимости.
Не переписываешь коммерческий оффер.
Не меняешь визуальный стиль сайта.
Не создаёшь новые большие разделы без отдельного задания.
Сначала проводишь аудит, затем вносишь только безопасные технические улучшения первого уровня.

ЦЕЛЬ
Усилить индексируемость и понятность сайта gostnik.ru для поисковых роботов Google и Яндекса.

ЭТАП 1 — АУДИТ
Нужно проверить и описать текущее состояние:

1. Индексация и техоснова
- наличие robots.txt
- наличие sitemap.xml
- корректность canonical
- отсутствие accidental noindex / nofollow
- корректность title и meta description на главной
- наличие favicon / og / twitter meta

2. HTML-структура
- один ли H1 на странице
- логична ли иерархия H2/H3
- нет ли дублирующихся или пустых заголовков
- нет ли избыточного SEO-шума в DOM

3. Изображения
- есть ли meaningful alt-тексты
- нет ли большого количества бессмысленных alt вроде “Фото 1”
- нет ли критичных изображений без alt

4. Structured Data
- какая JSON-LD разметка уже есть
- соответствует ли она реальному контенту страницы
- есть ли ошибки или неполные поля
- подходит ли тип schema для сайта:
  Organization / LocalBusiness / LodgingBusiness / другое

5. Контентная архитектура
- есть ли отдельные индексируемые страницы квартир
- если нет, отметить это как главный SEO-лимит
- есть ли отдельные страницы по городам Санкт-Петербург и Кисловодск
- если нет, отметить это как следующий этап

ЭТАП 2 — БЕЗОПАСНЫЕ SEO-ПРАВКИ ПЕРВОГО УРОВНЯ
После аудита внести только безопасные технические изменения, если они реально нужны:

1. Robots и sitemap
- если robots.txt отсутствует, создать корректный robots.txt
- если sitemap.xml отсутствует, создать sitemap.xml для текущих индексируемых URL
- добавить ссылку на sitemap в robots.txt

2. Meta и canonical
- исправить только при явной ошибке
- не переписывать удачные title/description без причины

3. Structured Data
- привести JSON-LD в корректный и полезный вид
- использовать только ту разметку, которая соответствует видимому контенту
- не добавлять фальшивые rating/review fields, если они не подтверждены корректной схемой
- если уместно, сделать аккуратную schema разметку для бренда и контактов на главной

4. HTML-семантика
- исправить только явные ошибки в heading structure
- улучшить alt у ключевых изображений, если сейчас alt слишком слабые или бессмысленные

ЗАПРЕЩЕНО
- не создавать новые страницы квартир на этом этапе
- не делать редизайн
- не переписывать все тексты
- не менять цены, отзывы, формы, маршруты
- не внедрять сомнительные SEO-хаки
- не набивать страницу ключевыми словами
